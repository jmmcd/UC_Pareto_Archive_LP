# UC_Pareto_Archive_LP

Solving multi-objective Unit Commitment or Economic Dispatch problems with objective weighting, LP, and Pareto Archive search among weightings, and epsilon-constraint grid search


This code is used in a working paper on viability of decentralised solar energy with a case study in Serbia, James McDermott, Ivan Stevovic, Raziyeh Farmani, Svetlana Stevovic.

## Repo Layout

```
data/           inputs: demand, plant info, solar production
src/            run.py (solver), duals.py, sensitivity.py, scenarios.py,
                feasibility.py, ParetoArchive.py
scripts/        run_exps.sh, analysis notebook
runs/           raw output of run.py — NOT in git
                (alternative scenarios under runs/scenarios/<name>/)
paper/figures/  figures for the manuscript (\includegraphics)
paper/tables/   LaTeX table fragments (\input)
derived/        small summary CSVs
```

The split is by what consumes a file, not by which script wrote it.
`runs/` is bulk output — ~19k small `.dat`/`.npy` files, ~180MB — and is
git-ignored, since it is regenerable from `src/` and `data/`. Everything
under `paper/` and `derived/` is small, tracked, and paper-facing.

Some files in `derived/` are also intermediates: `sensitivity.py` writes
`schedule_*.csv` there and the notebook reads them back to make figures,
so the notebook can be run without re-solving.

Reproduce in this order: `scripts/run_exps.sh` (slow, populates `runs/`),
then `src/duals.py` and `src/sensitivity.py`, then the notebook.
`src/feasibility.py` (seconds, needs no runs) shows that the summer
demand days in `data/demand.csv` have no feasible schedule.

## Alternative scenarios

Reviewer-requested sensitivity runs, each changing one input against the
baseline (not crossed with each other). They are defined in `SCENARIOS`
in `src/run.py`:

| scenario | change |
|---|---|
| `solar_d5`, `solar_d10`, `solar_d178.83` | New Solar sits 5 / 10 / 178.83 km from the load, so loses `k * d` of its output (baseline 0 km) |
| `solar_cost_5.7`, `solar_cost_4.8` | production cost of both solar plants, EUR c/kWh (baseline 6.6) |
| `coal_co2_1.6` | emissions of every lignite plant, kg CO2/kWh (baseline 0.82; gas unchanged) |
| `update_2026` | 2026 prices and coefficients, all at once: reads `data/2026/`, generated by `data/2026/make_2026.py` (see its docstring for every change) |

`RUN_SCENARIOS=true scripts/run_exps.sh` reruns every algorithm at every
solar size for each scenario (~4h per scenario; set `SCENARIOS="..."`
to run a subset, e.g. one per shell in parallel). Then `src/scenarios.py`
writes the figures (`paper/figures/scenario_*.pdf`,
`pareto_front_pairgrid_scenario_*.pdf`), tables
(`paper/tables/scenarios_*.tex`) and `derived/scenarios_*.csv`.
